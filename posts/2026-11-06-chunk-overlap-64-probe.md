# 每个块都以前一块的尾巴开头：64 字符 overlap 怎么骗过探针

## 现象：字段填上了，值有三成多是错的

页码字段填充率从 23.0%（226/981）提到 89.1%（874/981）之后，我没敢直接收工，抽了 47 个文本块回原文比对：取块内容、去掉 `[第N页]` 标记和空白，拿前 40 字去 `page_number` 所指那一页的原文里找。

命中率 63.8%。

字段填满了，但三分之一是错的。这比字段全为 0 更难发现——0 一眼就看出来，错值看起来一切正常，还会被引用到回答里。

## 定位：先看块的头部长什么样

第一反应是 `_resolve_pages` 的判定写错了。把几个未命中块的前 80 个字符打印出来，第一行是上一页的句子，到第 65 个字符之后才是本页的内容。

回看 `_add_overlap`：

```python
def _add_overlap(self, chunks: List[str]) -> List[str]:
    overlapped = [chunks[0]]
    for i in range(1, len(chunks)):
        prev = chunks[i - 1]
        overlap_text = prev[-self.chunk_overlap:] if len(prev) > self.chunk_overlap else prev
        overlapped.append(overlap_text + chunks[i])
    return overlapped
```

生产参数是 `FinanceChunker(512, 64)`。除了第一块，每个块的开头都多了前一块的最后 64 个字符。而探针取 40 字——**40 小于 64**，意味着探针从头到尾都待在 overlap 区里，一个字都没碰到本块自己的内容。

所以 63.8% 里有一大半不是页码错了，是探针在量上一页。测量工具自己没被测量过。

顺带一个从代码直接算出来的账：`_recursive_chunk` 先保证每块不超过 512，`_add_overlap` 再往前接 64 个字符，所以最终每块最长 576。名义 `chunk_size` 是 512，真正落进向量库的块最多 576；下游若按 512 排上下文预算，会稳定溢出约 12.5%。

更绕的一层：`chunk()` 是先 `_recursive_chunk()`（内部已经加过 overlap）再 `_resolve_pages()`。页码判定拿到的文本，每个块头都掺了上一块的尾巴。这也解释了 `_resolve_pages` 里那句 `head_tolerance = self.chunk_overlap + 8` 为什么必须留着——页标记如果刚好落在 overlap 之后，位置约等于 64，不给它 72 的余量就会被误判成「标记在块中部」。

## 修法：把测量和判定分开改

**一，探针避开 overlap。** 长度超过 64 就先切掉前 64 个字符，再取 40 字作探针：

```python
body = norm(PAGE_MARK.sub('', c.content))
# 块开头有 64 字符 overlap（来自上一块/上一页），探针要避开它
if len(norm(c.content)) > 64:
    body = body[64:]
if len(body) < 40:
    skip += 1
    continue
probe = body[:40]
```

**二，判定从「块内第一个标记」改成「标记的位置」。** 标记紧贴开头（≤ 72）→ 本块从该页开始；标记落在块中部 → 前半段承自上一页，本块是跨页块，起始页继承上一块末页，区间写进 `metadata["start_page"] / ["end_page"]`；块内没有标记 → 续块，整块继承上一块末页。

## 结果

同一批 47 个抽样块，三个版本的准确率：

| 版本 | 页码准确率 |
|---|---|
| 取块内首个标记 | 63.8% |
| 探针避开 overlap 后 | 97.9% |
| 按标记位置判定起始页 | 100%（47/47） |

第二行到第三行之间那 2.1%，剩的是跨页块：块头属于上一页、块尾已经翻页，只记一个页码必然有一半内容对不上，所以改成记区间而不是记单点。

再把新旧分块器在同样 10 篇原件上逐块 diff：分块总数 981 对 981，内容完全一致 981/981，333 块页码不变，648 块从 0 变成正数，异常 0。改的只有页码字段，块边界、块内容、块类型、块序号一个没动。

## 可搬走的一句

64 不是坏参数。它保证跨块检索时句子不被切断，这个收益是真的。坏的是下游把它当成语义边界：探针把「块的前 40 字」当成「本块的正文」，判定把「块内第一个页标记」当成「本块起始页」。这两个假设在 overlap=0 时都成立，在 overlap=64 时都不成立。

落到动作上：任何依赖「块开头 N 个字符」的探针、分类器、相似度计算，先确认 N 和 overlap 的大小关系。**N ≤ overlap 时，你量的全是上一块。**
